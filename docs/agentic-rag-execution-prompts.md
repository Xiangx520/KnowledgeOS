# Agentic RAG 实施提示词

日期：2026-11-08  
配套计划：[agentic-rag-migration-plan.md](agentic-rag-migration-plan.md)。实施结果见[实施说明](agentic-rag-implementation.md)；下文仍是给后续编码 agent 的任务指令模板，不是已实现功能说明。

## 1. 整体执行提示词

适合让一个 agent 连续推进完整转化。将以下内容复制到项目中的新对话；路径相对 `rag-knowledge-assistant` 根目录。若当前目录是其父目录，先定位实际项目根目录。

```text
请实际实施本项目向 agentic RAG 的转化，不要只输出建议。

先阅读适用的 AGENTS.md、docs/agentic-rag-migration-plan.md 和本项目相关源码；以实际代码为准核实计划中的基线。遵守工作区已有修改，不重置或覆盖他人工作。计划中的新增模块和配置目前是设计，不要假定它们已存在。

目标：在现有 standard 流程保持兼容的前提下，为 mode=agent 增加受特性开关控制、预算有界的单 agent 检索循环。它必须根据实际工具观察选择下一步，支持把第一跳发现的实体用于第二跳查询，并将核验发现的证据缺口反馈给检索。不能只把固定检索重试重命名为 agent。

按计划 P0→P5 顺序实施，阶段间依赖必须通过验收。优先做可运行的纵向闭环，再完善产品与运行保障。每阶段完成后更新计划第 9 节：改动文件、运行命令、实际结果、限制及下一步。不要在只实现工具壳或 mock 测试后宣称完成整个转化。

关键要求：
1. 复用 CorpusScope、现有检索、模型适配器和生成/核验逻辑。所有读工具在当前授权与活动版本范围内运行，模型不能指定用户、任意 scope、路径、URL 或 SQL。
2. 冻结用户目标和约束；将动态任务、依赖和派生实体另存于执行状态。派生实体及其关系必须有原文来源；完整保存邻块来源，最终复验所有实际引用。
3. 结构化策略输出经过严格 schema/ID/约束校验，模型结果不能直接执行。限制步骤、工具、模型尝试、token、时限和输出大小；失败重试也计入预算。为生成和核验预留预算。
4. 贯通 effective settings，核对配额粒度、租约、capacity TTL、心跳、取消与总时限。每次工具前和最终发布前检查权限及版本，撤权/版本冲突不得以降级路径绕过。
5. 核验缺口可以触发有界补检索；无关内容删除，核验器异常失败关闭。numeric 只能标记部分检查。没有语义核验时不得宣称综合事实答案已核验，可安全摘录或拒答。
6. 保留 standard、旧 agent 回退、现有响应字段及 SSE 事件。前端 done 替换草稿与引用，避免重写后拼接或错号。新循环首期绕开答案缓存，但保留请求幂等和权限复验。
7. trace 记录动作、结果 ID、预算和停止原因，不存模型隐式思维链，不记录密钥，不复制无限量原文。
8. 首期不加入多 agent、公网搜索、外部写操作、任意代码工具，也不重做摄取和索引体系。不自动部署生产环境或运行破坏性迁移。

验证：先建立 standard/旧 agent 基线和多跳 fixtures；用可注入策略测试状态机，用实际数据库/授权入口测隔离；覆盖完整证据链、观察改变动作、缺口恢复、冲突、预算、取消、撤权/版本切换、幂等和 SSE 最终一致性。执行相关 pytest、ruff 和前端 build。再按计划做真实模型配对评测，记录模型、配置、样本、成本和延迟。

无真实模型凭据时继续完成离线实现与测试，并明确“真实模型验收未完成”，不得伪造质量数字。遇到环境问题完成不受影响的部分；只在确实缺少必要信息或需要超出授权范围时提问。常规技术选择自行决定并记录理由。

最终交付：实现了哪些阶段、关键改动与文件、实际验证结果、未通过/未运行项、如何开启/关闭新模式、当前限制和下一步。更新文档，不自动提交、推送或部署。
```

## 2. 分阶段执行提示词

适合每次交给一个新的 agent，控制改动范围。先复制“共同前置指令”，再复制本次阶段指令。阶段按顺序串行推进，不要求并行 agent 工作。

### 共同前置指令

```text
请在实际项目中实施下面指定阶段。先阅读适用 AGENTS.md、docs/agentic-rag-migration-plan.md、该文档第 9 节的进度和相关源码。核对前置阶段产物与实际测试，保护现有工作区修改。执行计划第 5 节的预算、权限、版本、取消、配置、兼容和降级约束。

本次只完成指定阶段及必要前置修复，不自动进入下一阶段。提供可 review 的代码与必要行为测试，更新第 9 节进度，列出实际运行命令/结果、未运行原因和交接注意事项。不把设计写成已实现，不凭 mock 测试宣称真实模型效果，不提交/推送/部署。
```

### P0：基线与评测夹具

```text
实施 P0。核对聊天入口、intent、retrieve_plan、CorpusScope、生成核验、有效配置、SSE、配额和租约。跑当前适用检查并保存真实结果；建立 standard/旧 agent 配对基线和可离线复现的多文档评测夹具，先标注预期证据链与停止行为。

至少设计“制度→审批角色→授权表”的依赖两跳案例、不同第一跳导致不同第二跳的变体、比较缺一侧、冲突、无证据和关键条件歧义。确保第二跳关键事实不会被第一跳直接返回。明确新增 benchmark 的输入输出、模型调用模式和无模型模式。冻结后续验收集，输出简短架构决策。本阶段不更改生产控制流。
```

### P1：状态与工具

```text
实施 P1。基于 P0 契约新增 agent 状态、判别联合动作、任务 DAG、带出处绑定、证据账本和统一预算上下文；封装 search/read_context/lookup_reference。配置要经过有效配置链，不让深层 get_settings 忽略运行时覆盖。

重点测试工具授权、失效版本、邻块溯源、未知 ID、伪造绑定关系、依赖环、动作去重、大小限制和调用预算。检索摘要不能代替原文；不得新增越权读取入口。本阶段可不接入真实策略循环，standard 保持原行为。
```

### P2：动态策略与循环

```text
实施 P2。新增 agent policy/runner，经特性开关接入 mode=agent，保留 standard 与旧 agent 回退。模型根据当前观察选择受限动作，允许新增有出处的依赖子任务，支持提前停止和有界非法输出纠正。保持冻结的用户目标、约束及工具权限边界。

用脚本化策略证明第一跳实体驱动第二跳，改变第一跳观察会改变第二跳；真实查询经过工具而非把全量材料塞入 prompt。覆盖重复动作、无进展、总预算和 deadline。按可用环境完成至少一个真实模型多跳冒烟；未执行必须写明，不伪造通过。
```

### P3：核验补证据

```text
实施 P3。将 answering 中生成、核验和最终化抽成共享路径，防止 standard 与 agent 复制分叉。扩展结构化核验缺口，将 missing_evidence/unsupported_claim 等可恢复问题反馈给 runner，按预算最多一轮补证据，之后再次生成核验或安全结束。

测试补检索由核验反馈实际触发；不可补齐时明确缺失部分；比较保留双方证据；冲突不自选胜者；verifier 不可用失败关闭；numeric 不标语义通过。最终引用只保留使用来源，覆盖所有邻块和版本检查。
```

### P4：前端与运行保障

```text
实施 P4。完成 SSE/非流式契约、前端最终替换、能力声明、有效配置和示例、精简 metadata/trace、指标与使用文档。贯通总时限、模型尝试计量、用户配额、并发容量/会话租约、取消与幂等。新 agent 绕开答案缓存，standard 行为保持兼容。

集成测试覆盖运行中撤权、切换版本、取消、不重复执行的 request_id、重放授权、最终 answer/citations 一致性，以及关闭开关回退。跑相关后端测试、ruff、前端构建，记录真实结果。本阶段不默认开放或部署。
```

### P5：效果评测与发布判定

```text
实施 P5。先审查 P0—P4 的实现与验证证据，再在冻结的验收集上配对比较 standard、旧 agent、新 agent。保持同语料、模型和参数，核心多跳集重复试验，记录证据链成功率、任务完成率、逐事实支持率、拒答/澄清、约束违反、调用/token、p50/p95 延迟和预算终止比例。

按计划第 7 节作出明确通过/不通过判定，并提供可复现的报告与原始结果（不含密钥/敏感全文）。人工抽检评审结果，防止用同一个模型的自评代替证据。缺少真实模型环境时仅完成可执行评测入口和离线检查，将真实验收标为未完成，不放宽门槛伪造成功。验证回退，更新实际能力说明，保持默认开关 false，不执行生产发布。
```

## 3. 中断后的续做提示词

```text
请接续本项目的 agentic RAG 转化。先读 docs/agentic-rag-migration-plan.md 第 9 节，核对实际文件、工作区差异和验证记录。不要从零重写已完成模块。找出最早尚未完成验收的阶段，从该处继续，修复前置缺口并保护已有兼容性。沿用 docs/agentic-rag-execution-prompts.md 的整体约束；本轮结束时更新进度，说明已经完成、仍待验证以及下一步。
```
